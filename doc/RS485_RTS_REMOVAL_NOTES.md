# RS485控制引脚移除说明

## 修改概述

移除了RS485收发控制引脚(RTS)相关的所有代码，简化了硬件连接和软件配置。

## 具体修改

### 1. 主程序修改 (`main/main.c`)
- ✅ 移除 `RS485_RTS_PIN` 和 `USE_RS485_RTS` 宏定义
- ✅ 简化 `uart1_init()` 函数，统一使用标准UART模式
- ✅ 移除条件编译的RS485半双工模式配置
- ✅ 简化启动日志输出

### 2. 配置文件修改 (`main/battery_config.h`)
- ✅ 移除RS485控制引脚相关配置项
- ✅ 更新使用说明，去掉RTS控制相关描述

### 3. 文档更新 (`doc/UNIFIED_UART_README.md`)
- ✅ 更新配置示例，移除RTS引脚配置
- ✅ 简化硬件连接图，去掉RTS引脚连线
- ✅ 更新配置说明

## 硬件连接简化

**修改前** (复杂):
```
ESP32S3          RS485模块        BMS
GPIO16(TX)  -->  DI       
GPIO17(RX)  -->  RO              
GPIO42(RTS) -->  DE/RE (可选)     
                 A        -->     A
                 B        -->     B
```

**修改后** (简化):
```
ESP32S3          RS485模块        BMS
GPIO16(TX)  -->  DI       
GPIO17(RX)  -->  RO              
                 A        -->     A
                 B        -->     B
```

## 功能影响

### ✅ 保持不变的功能
- RS485电池查询功能完全正常
- JSON被动控制功能完全正常
- 所有四种工作模式正常
- 显示功能和UI界面不变

### 🔧 简化的部分
- 不再需要GPIO42作为RTS控制引脚
- 不再支持RS485半双工模式切换
- 硬件连接更简单，只需TX/RX两根线
- 软件配置更简洁，减少配置选项

## 注意事项

1. **硬件兼容性**: 
   - 如果之前连接了GPIO42到RS485模块的DE/RE引脚，现在可以断开
   - 大多数RS485模块都有自动收发切换功能，不需要手动控制

2. **软件兼容性**:
   - 原有的配置文件仍然兼容
   - 重新编译后即可使用简化版本

3. **通信稳定性**:
   - 标准UART模式在大多数应用中工作正常
   - 如需更严格的RS485时序控制，可考虑使用带自动收发切换的RS485模块

## 验证步骤

1. **重新编译**: 确保代码编译无错误
2. **硬件检查**: 确认GPIO42未连接或已断开
3. **功能测试**: 验证RS485电池查询和JSON控制功能正常
